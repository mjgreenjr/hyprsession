# v1.2 fix brief — restore fidelity (fix before finishing the playtest)

**Decision (Mike, Oct 30):** the v1.2 playtest stops after stage 1. The two defects
below are fixed on branch `v1.2/plan` first; afterwards the FULL convergence
protocol re-runs from a fresh v12-a. Rationale: the playtest target is Mike's
working desktop — every load on the current build costs manual repairs, and a
B snapshot would bake load A's damage in as the new baseline.

Playtest stage-1 results that stand: computed insertion order used on
workspaces 1, 2, 3, 5, 6, 7, 8, 9, 10; WS4 fell back to saved reading order
(reason: "the saved tree is not one dwindle grows with the pointer at
(1311, 504)") — a data point to re-measure on the re-run, not part of this fix.

## Defect 1 — wrapper blindness at save (a restored session loses its resume)

Evidence (snapshot v12-a, load log, source):

- clients.json: the WS4 terminal titled "✳ Lions game score not updating"
  (cwd `/home/mike/Work/playcall-gui`, at [12,38], size [941,508]) has **no
  `foreground` record**. Only three windows in the snapshot have one (a bash,
  a codex, a claude — all hand-launched), and those are exactly the three
  resumes the load dispatched.
- exec.conf for the same window carries the full wrapper line ending in
  `'claude --continue'` — copied from the foot process's own /proc cmdline.
- `src/procfs.rs` `capture_terminal`: a program is recorded only if its
  process group is the tty's foreground group and differs from the shell's
  group. Under the `hyprsession-resume` wrapper (non-interactive `sh -c`,
  no job control) the resumed program shares the wrapper shell's group, so
  the probe records nothing. The session was live but idle (Mike, eyewitness).
- `src/session.rs` `capture_all` already detects this case — it strips the
  wrapper from the recorded argv ("record the terminal itself") — but the
  recovered (cwd, command) is never written into the `foreground` record.
- The loader launches new-format snapshots from clients.json only
  (session.rs: exec.conf "remains the launch source only for legacy
  snapshots"), so the truth sat in the file the loader doesn't use.

**Requirement:** when a terminal's argv carries the resume wrapper, record
the recovered (cwd, command) where the loader dispatches from — the
`foreground` record, passed through the existing resume-table decision —
so a restored session survives the next save→load cycle with its resume
intact. Preserve existing guards: the hyprsession-itself-in-foreground
self-guard, the ambiguous multi-shell warning/skip, `linked` semantics.

## Defect 2 — claiming race at load (a resumed window binds to the wrong entry)

Evidence (load-A log + Mike's eyewitness):

- The snapshot's Sennheiser Claude (saved WS1, `claude --continue` at
  /home/mike) was dispatched, but Mike found it running in a `~` terminal
  on **WS8**; WS1 received a plain `~` shell instead.
- A freshly spawned resume window wears the generic `mike@omarchy:~` title
  until the resumed program retitles it. Five saved windows share that
  title; claiming by title binds the window to whichever identical entry
  is flushed before the retitle lands. Nothing orders the retitle first.

**Requirement:** a spawned resume window must bind to the saved entry whose
command it is running. The binding must not depend on the window's
transient title when identical titles exist. (The loader dispatched the
exec itself — the wrapper's cwd + command identify the entry; how to carry
that identity to the claim is the implementer's choice.)

## Acceptance

- `cargo test` green, plus new tests: (a) wrapper-terminal save records a
  dispatchable resume, including the second-generation case (a terminal
  produced by a load records correctly at the next save); (b) spawn
  binding with duplicate titles binds each resume window to its own entry.
- All live claims PENDING, as with the implementation: Mike's re-run of
  the full protocol (fresh A → B → C, both diffs, per-workspace order
  lines) is the verdict, with two scenario checks added:
  - *Lions:* a live session in a wrapper-launched terminal keeps its
    resume across save → load → save.
  - *Sennheiser:* a resumed window lands on its saved workspace.

the always-on package (still after v1.2); any change to claiming for
non-resume windows beyond what Defect 2's requirement forces.
