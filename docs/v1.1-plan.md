### 0.2 Data model changes (all additive, all optional)

`clients.json` entry today = `Client` fields + optional `argv`, `cwd`. v1.1 adds one optional key,
**`foreground`**, only on terminal windows where a non-shell foreground program was found:

```json
"foreground": { "pid": 4242, "argv": ["claude"], "cwd": "/home/synthetic/proj", "linked": false }
```

* `pid` — foreground leader pid at save time (needed for the linkage rule; excluded from fingerprints).
* `argv`, `cwd` — read from `/proc/<pid>/cmdline` and `/proc/<pid>/cwd`.
* `linked` — true iff `pid` equals the `client.pid` of **another** saved client (exact pid identity).

Back-compat is by construction: `SavedClient::try_from` already strips the extras it knows and hands
the remainder to `Client`'s deserializer, which ignores unknown keys (the existing
`plain: Vec<Client>` assertion in `test_saved_client_round_trip_with_argv_and_cwd` proves the
older-consumer direction). The new key is stripped the same way; absent → `None`; `None` is not
serialized, so old snapshots round-trip byte-for-byte as they do now. A malformed `foreground`
value is treated as absent (same leniency as `argv`/`cwd`).

`SavedClient { client, argv, cwd }` is built with struct literals at roughly 14 sites (about 11 in `session.rs`
tests/code, 3 in `load.rs` tests). Adding a field forces a mechanical update of those literals; plan
is a `SavedClient::new(client, argv, cwd)` helper used by the tests so future fields don't repeat
this churn.

### 0.3 Launch model (replaces the current `ExecEntry { rules, command }`)

```rust
pub struct ExecEntry {
    pub rules: ExecRules,
    pub command: String,          // ready to hand to Op::Exec (cwd wrap / terminal wrap applied)
    pub group: Option<GroupInfo>, // None for legacy exec.conf entries -> V3/V5 skipped, v1 behavior
}
pub struct GroupInfo {
    pub label: String,            // unwrapped recorded command, for reports
    pub saved: Vec<usize>,        // indices into LoadPlan.saved belonging to this launch group
}
```

A "launch group" is exactly what `launch_entries_from_saved` already computes: the distinct
`(command, pid)` pair; `saved` collects every saved window of that pair, so
`expected = saved.len()`. `parse_exec_line` sets `group: None`, so legacy plans compare equal to
today's (existing `test_legacy_snapshot_follows_the_exec_conf_path` stays valid unchanged).
`LoadPlan` gains `scope: Option<i32>` and `resume: ResumeConfig`-free data only (all resume
decisions are made at plan time, so `run_load` stays host-only and testable with `FakeHost`).
`LoadPlan` literals (7 in `load.rs` tests, 1 in `session.rs`) get `scope: None`.

## V1 — cwd-on-load

**Design.** In `launch_entries_from_saved`, after the command string is final (verbatim blob / shell-joined
argv / sandbox-substituted desktop-entry command), if `window.cwd` is `Some(dir)`:

* `Path::new(dir).is_dir()` → `command = format!("cd {} && {}", shell_quote(dir), command)`.
* otherwise → print `Warning: working directory '<dir>' of '<title>' (<class>) no longer exists; launching from the loader's directory` and leave the command unwrapped.
* `cwd: None` → untouched (legacy / v1 behavior).
* **Ruling Q5:** a sandbox-substituted window (`is_sandbox_internal` argv) skips the wrap **and** the warning, silently — its recorded cwd is a sandbox path and `flatpak run` sets its own.

Per DEC-1 this applies to every launch with a recorded cwd, not only relative-path ones. The
`launched` dedup key and `group_rules` key stay on the **unwrapped** command, so grouping and
"one launch per distinct pid" are unchanged. The existence check goes through an injectable
`dir_exists: &dyn Fn(&Path) -> bool` parameter (default `Path::is_dir`) so tests don't depend on
the filesystem.

`cd X && cmd` runs inside Hyprland's `sh -c`; the window's pid is the app's own pid either way, so
pid-keyed logic is unaffected. `shell_quote` already handles spaces/quotes in paths.

**Touched:** `load::launch_entries_from_saved` (+ a small `wrap_cwd` helper). Legacy path
(`parse_exec_conf`) untouched — exec.conf has no cwd.

**`--simulate`:** the `exec_cmd` line shows the wrapped command; the missing-dir warning prints
during planning, so simulate shows it too.

**Ruling Q5 (changed):** Flatpak/sandbox-internal windows record a cwd as seen from inside the
sandbox, often not a host path. They are exempt from DEC-1: no wrap, no warning.

## V2 — Inside-terminal restore

### V2.1 Capture (save)

New `procfs.rs`:

```rust
pub trait ProcFs {
    fn pids(&self) -> Vec<i32>;
    fn stat(&self, pid: i32) -> Option<ProcStat>;   // ppid, pgrp, session, tty_nr, tpgid
    fn argv(&self, pid: i32) -> Option<Vec<String>>;
    fn cwd(&self, pid: i32) -> Option<String>;
}
```

`ProcStat` is parsed from `/proc/<pid>/stat`, locating fields **after the last `)`** (the `comm` field
can contain spaces and parentheses): after it come `state ppid pgrp session tty_nr tpgid …`.
`RealProc` reads `/proc`; tests use `FakeProc` (a map pid → stat/argv/cwd).

**Which windows are terminals.** A window is a terminal iff its process (basename of argv[0] after
program-identity resolution, §V2.3; `/proc/<pid>/exe` basename as a second chance) is a key of the
terminal-profile table (§V2.4). Class names are *not* used (process identity is what the brief
specifies, and classes vary: `Alacritty`, `com.mitchellh.ghostty`, …). Structural pty detection alone
is rejected: IDEs and editors hold ptys too, and relaunching "their foreground program" inside them
would be wrong.

**Walk.** `capture_foreground(proc, window_pid) -> Option<Foreground>`:

1. Build a ppid → children index from one pass over `proc.pids()` (portable; does not rely on
   `CONFIG_PROC_CHILDREN`).
2. BFS from `window_pid` (depth bounded, e.g. 8) collecting **shell candidates**: descendants that are
   session leaders (`session == pid`) with a controlling tty (`tty_nr != 0`).
3. Exactly one shell candidate required (**A6:** that shell's `/proc/<pid>/cwd` is recorded as the terminal *client's* `cwd`, replacing the terminal process's own cwd, since the shell may have `cd`'d; terminals only). Zero → nothing to record. More than one → the terminal
   process owns several ptys (server-mode / multi-window process); the pid walk cannot say which pty
   belongs to which saved window → record nothing and print a warning **[FLAG Q4]**.
4. `fg_pgrp = stat(shell).tpgid`. If `fg_pgrp == shell.pgrp` (the shell holds its own tty foreground)
   → the shell itself is foreground → record nothing. `tpgid <= 0` (no foreground) → record nothing.
5. The foreground program is the process with `pid == fg_pgrp` (group leader). If the leader is gone
   (pipeline whose leader exited), fall back to the lowest-pid process with `pgrp == fg_pgrp` and the
   same `tty_nr`. Record its argv and `/proc/<pid>/cwd`; a program whose argv/cwd are unreadable
   (exited between reads, permission) → record nothing, never fail the save.

A pipeline (`a | b`) is recorded as its leader only — documented limitation.

**Linkage rule (ruling Q12, extended beyond the leader).** Capture is restructured from per-client to
per-snapshot: `SavedClient::capture_all(clients, &dyn ProcFs) -> Vec<SavedClient>`. At capture the
foreground record also collects `group_pids` (every pid in the foreground process group) and
`descendant_pids` (every descendant of the foreground leader), used transiently. A record is
`linked = true` iff any pid in the foreground process group **or** any descendant of the foreground
leader equals the `client.pid` of **another** saved client. Exact pid equality only; no
command-string matching. This covers a wrapper script that forks the real GUI. Capture test: leader
pid differs from the client pid, a descendant of the leader equals it → linked. `save()` replaces
its per-client `SavedClient::capture(info)` call with one `capture_all` call (order preserved).

**Fixed-point requirements this forces (important — see §7):**

* *Terminal argv normalization.* After a v1.1 load a relaunched terminal's real argv is
  `foot … -e sh -c '…' hyprsession-resume …` (the wrapper, §V2.4). Re-saving would record the wrapper
  as the terminal's argv and the next load would nest another wrapper. Capture therefore strips a
  recognisable wrapper (the `hyprsession-resume` argv0 marker and everything from the profile's
  exec-introducer onward) back to the original terminal argv before storing `argv`. Without this the
  Phase 2 fixed point regresses for any terminal that carried a foreground record.
* *Foreground fingerprint.* A table-resumed program changes argv across a cycle
  (`claude` → `claude --continue`). The fingerprint's foreground component is therefore the
  **resolved relaunch command + fg cwd** (what load would run), not raw argv — see §V2.6.

### V2.3 Resume table representation (`resume.rs`)

Built-in defaults are data constants, keyed by program identity (lower-case basename):

```rust
pub const BUILTIN_RESUME: &[(&str, &str)] = &[
    ("claude", "claude --continue"),   ("muse", "muse resume --last"),
    ("codex", "codex resume --last"),  ("gemini", "gemini --resume"),
    ("aider", "aider --restore-chat-history"), ("opencode", "opencode --continue"),
    ("copilot", "copilot --continue"), ("goose", "goose session --resume"),
    ("qwen", "qwen --continue"),
];
```

Exactly the nine verified entries, nothing added, no generic fallback (fact 6). Values are complete
replacement command lines, stored and executed as text (shell-evaluated at relaunch, §V2.4).

**User file** (DEC-3): `$XDG_CONFIG_HOME/hyprsession/resume.toml`, falling back to
`~/.config/hyprsession/resume.toml` — identical to the DEC-3 path in the default environment.

```toml
[settings]
unlisted = "replay"      # DEC-2: "replay" (verbatim argv, default) | "prompt" (clean prompt)

[resume]                 # extends/overrides built-ins per key
claude = "claude --continue --model sonnet"
aider  = ""              # empty string = explicitly resume nothing (clean prompt)
mytool = "mytool --last"

[terminals]              # optional: extend the terminal-profile set (see V2.4)
extra = ["myterm"]
```

`ResumeConfig::load(path_opt) -> Result<ResumeConfig, String>`: built-ins ⊕ file. Missing file → built-ins.
Parse error → **hard error from `prepare_load`, before `clear()`, naming the file, line and problem, and surfaced under `--simulate` too (simulate runs `prepare_load`)** (same principle as a bad
`clients.json` today; a typo must not silently drop overrides) **[FLAG Q7]**. Pure function
`ResumeConfig::decide(&Foreground) -> RelaunchDecision`:

```rust
enum RelaunchDecision { Linked, Table{cmd}, Replay{cmd}, CleanPrompt{reason} }
```

* `foreground.linked` → `Linked` (nothing relaunched).
* identity in table → `Table` (empty-string override → `CleanPrompt`).
* otherwise `settings.unlisted`: `replay` → `Replay{ shell_join(argv) }`; `prompt` → `CleanPrompt`.

**Program identity.** Basename of argv[0]. Terminal agents shipped as npm/pip scripts present as an
interpreter (`node /…/bin/codex`, `python3 /…/aider`), so basename-of-argv0 would be `node`/`python3`
and never hit the table. Plan: if argv[0]'s basename is a known interpreter (`node`, `nodejs`, `bun`,
`deno`, `python`, `python3*`, `ruby`, `perl`, `sh`, `bash`, `env`), skip option words (`-…`) and — when resolving through `env` — also `KEY=value` words, and use the
basename of the first remaining argument, stripping a trailing `.js/.mjs/.py`. **[FLAG Q3]** — this
goes beyond "keyed by program basename" in the brief; it is the difference between the table working
or being dead for node-based CLIs.

### V2.4 Terminal relaunch mechanism

*Terminal profiles* (`resume.rs`): `TERMINAL_PROFILES: &[(&str /*basename*/, ExecStyle)]` where
`ExecStyle` is `Flag("-e")` (arguments after `-e`) or `Positional` (command words appended; kitty/foot
form). **Ruling Q4:** profiles are data; a profile ships enabled only with a vendor-doc citation recorded
here, and `foot` must be one. Enabled set and citations (fetched during implementation):

| Terminal | Exec form | Citation |
|---|---|---|
| `foot` | `Positional` — trailing non-option args are the command | foot man page source, `doc/foot.1.scd` (gitlab.com/dnkl/foot): "*foot* [_OPTIONS_] <_command_> [_COMMAND OPTIONS_] — All trailing (non-option) arguments are treated as a command" |
| `kitty` | `Positional` — `kitty [options] [program-to-run ...]` | kitty `kitty/cli.py` usage string `[program-to-run ...]` and the `kitty --hold sh -c "…"` example (github.com/kovidgoyal/kitty) |
| `alacritty` | `Flag("-e")` — command and args after `-e`, "must be last argument" | `extra/man/alacritty.1.scd` (github.com/alacritty/alacritty): "*-e, --command* <COMMAND>... Command and args to execute (must be last argument)" |

All other terminals (xterm, urxvt, st, ghostty, …) are not enabled in v1.1: they may be *detected*
only if present in the table, so they are not listed; adding one later requires a citation.
Anything detected-but-unverified (user `[terminals] extra`) degrades to a clean prompt with a warning; a terminal that is detected but has no verified profile is captured but
relaunched as a clean prompt with a warning. Multi-window-per-process terminals (gnome-terminal-server,
konsole, wezterm mux) are excluded by the single-pty rule (V2.1 step 3). **[FLAG Q4]**

*Command construction* (`build_terminal_launch(terminal_cmd, profile, decision, fg_cwd) -> String`),
producing one `Op::Exec` string:

```
cd <terminal cwd> && <terminal command> <exec-introducer> sh -c '<SCRIPT>' hyprsession-resume <fg cwd> <resume command text>
SCRIPT = cd "$1" 2>/dev/null; eval "$2"; exec "${SHELL:-/bin/sh}"
```

* The program runs under `sh -c` inside the terminal, so there is **one level of quoting** only:
  data (fg cwd, command text) travels as positional parameters `$1`/`$2`, never interpolated into
  the script. Replay commands are `shell_join(argv)` (existing, round-trip-tested quoting), table
  commands are the table text; both are `eval`ed from `$2`.
* **Drop-to-prompt.** After `eval` returns (program exited, any status), `exec "${SHELL:-/bin/sh}"`
  replaces the wrapper with the user's shell, so the window stays and sits at a prompt (acceptance
  2c). `exec` leaves no stray `sh`.
* The outer `cd <terminal's recorded cwd>` is the V1 wrap (unchanged — the terminal process keeps its
  own cwd, avoiding cwd drift in the re-saved snapshot); the inner `cd "$1"` puts the resumed program
  in the *foreground program's* recorded cwd. If the fg cwd is gone: warn (same text as V1, naming
  the window and directory) and skip the inner cd.
* `Linked` / `CleanPrompt` → no wrapper; the terminal launches as plain V1.
* The terminal's own recorded argv is kept as-is; the exec introducer + wrapper is appended textually
  (`xterm`-style "`-e` must be last" holds). A single-element blob terminal argv is appended to verbatim, as elsewhere.

*Where it plugs in:* `launch_entries_from_saved` gains `resume: &ResumeConfig`; for a window with
`foreground`, it calls `decide`, builds the command above, and keeps `GroupInfo.label` as the
terminal's unwrapped command. Decisions (`Table`/`Replay`/`Linked`/`CleanPrompt`) are also stored on
the entry for `--simulate`.

### V2.5 Load-time interaction with launch grouping

Launch stays one per distinct `(command, pid)`. Because capture refuses to record a foreground when a
terminal process owns more than one pty (V2.1), a pid that is shared by several saved windows never
carries a foreground, so "one launch per pid" and "one foreground per launch" cannot conflict.

### V2.6 Fingerprint

`session::fingerprint` appends a component per client: for `foreground = None`, a fixed empty marker
(so legacy comparisons behave as before — both sides are produced by the same function); otherwise
`(resolved relaunch command, fg cwd)` obtained through `ResumeConfig::decide` (`Linked` →
`"linked"`). `pid`/`linked-pid` are excluded. This makes
`save → load → save` converge for table-resumed programs (`claude` and `claude --continue` both
resolve to `claude --continue`) and for verbatim replay (argv identical).

**Touched:** `procfs.rs`, `resume.rs`, `session.rs` (`SavedClient`, `capture_all`, `save`,
`prepare_load`, `fingerprint`), `load.rs::launch_entries_from_saved`, `command_detection.rs`
(reuse `read_argv`/`read_cwd`/`shell_join`; no changes needed beyond maybe `pub(crate)`).

## V3 — Same-process window-count fulfillment

**Design.** Groups come from `GroupInfo` (§0.3). Placer targets gain a group tag:
`Placer::with_groups(Vec<(Client, Option<usize /*group idx*/>)>)`; `Placer::new` keeps working
(untagged), so existing placer tests are unchanged.

In `run_load`, for each entry with `group = Some(g)`, after the existing "first new window appears"
wait:

1. **Settle.** Poll (placing as today) until the group's claimed count is stable for `SETTLE_TICKS`
   (e.g. 3 s = 12 ticks) or reaches `expected`. Returns immediately when already complete, so a
   normal one-window launch costs nothing extra.
2. **Compare.** `claimed` = windows that appeared during this group's phase (addresses absent from the
   `before` set) and that the Placer claimed. Using "appeared during this phase" instead of "Placer
   targets tagged with this group" avoids the class-fungibility trap (Placer matches by class, so a
   newcomer can claim a sibling group's target). **[FLAG Q2]** — the brief says "claimed by the
   Placer"; this is the same count restricted to this group's window.
3. **Re-invoke.** `shortfall = expected − claimed`. While `shortfall > 0` and re-invocations used <
   initial shortfall: `Op::Exec(entry.command)` again (same cwd-wrapped command), settle-wait, place
   newcomers through the existing `place_live`/Placer, recompute. Hard bound: initial shortfall
   count of extra invocations. Never re-invoke when `claimed == 0` (a launch that produced nothing is
   a failure to report, not a reason to double-launch a slow starter) **[FLAG Q1]**.
4. **Report.** Persistent shortfall → `LoadReport.shortfalls.push(GroupShortfall { label, expected,
   got, reinvocations })` and a warning line; the unmatched saves are listed by the existing
   unmatched report; load completes.

Minted windows are never populated by the loader. Legacy plans (`group: None`) skip V3 entirely.
`ExecRules` placement for minted windows comes from the Placer (saved client geometry), not from rules.

**Touched:** `load::{Placer, run_load, LoadReport}`, new consts `SETTLE_TICKS`.

## V4 — Per-workspace load

**CLI.** `--workspace <N>` (`Option<i32>`, `main.rs`) → `LocalSession.workspace: Option<i32>` (new pub
field; the ~12 `LocalSession { .. }` literals in `tests/integration_tests.rs`, `sim_session`, and
`main.rs` get `workspace: None`). Accepted for `load` only; with any other mode it is an error
exit **[FLAG Q8]**. `N` must be a positive workspace id; special workspaces are out of scope
(brief parks id −99; named specials unspecified) → reject `N <= 0`.

**`prepare_load` slicing** (all before anything is touched): from the snapshot keep clients with
`client.workspace.id == N`; derive launch entries from that slice only (so shared-pid logic and
`expected` counts are slice-relative); `plan.saved` is the slice; `plan.scope = Some(N)`. If the slice
is empty → error before `clear()` ("snapshot has no windows on workspace N"). For legacy snapshots
(no argv) the exec.conf entries are filtered by `rules.workspace == Id(N)`; V1–V3/V5 do not apply to
them as today.

**Scoped clear — shared-pid guard.** `clear_session` is generalised, not forked, into
`clear_windows(host, config, scope: Scope)` with `Scope::All | Scope::Workspace(i32)`;
`clear_session(host, config)` stays as a thin wrapper (`Scope::All`), so every existing clear test and
the full-desktop path execute the same code. For `Scope::Workspace(n)`:

1. Snapshot `scope_set` = addresses of live windows whose `workspace.id == n` *at clear start*
   (address-based, so a window that is moved mid-clear doesn't change scope).
2. Graceful stage: `Op::Close` only for addresses in `scope_set`; wait until none of `scope_set`
   remains (`wait_until_gone(host, &scope_set, ticks)` replaces `wait_for_empty`; `wait_for_empty`
   becomes the `All` case).
3. Signal stages: from a **fresh** client list, a pid is *signal-eligible* iff `pid > 1` **and every
   live window of that pid has its address in `scope_set`**. Pids with at least one out-of-scope
   live window are *protected*: they receive no TERM and no KILL, ever. Eligibility is recomputed
   at each stage (windows can open/close in between).
4. Survivors that are protected → reported (`ClearReport.refused: Vec<…>` and a printed line naming
   window, class, pid, and "shared with workspace M; not signalled") and **do not abort**.
   Survivors that are eligible and outlive KILL → the existing abort error naming them. In
   `Scope::All` there are no out-of-scope windows, so the guard is vacuously true and behavior is
   byte-identical to today.
5. After a scoped clear with refused survivors the load continues **[FLAG Q6]** (they remain on N;
   see Q6 for how they interact with placing).

**Scoped launch/place.**

* Launch only the groups derived from the N slice (so shared-pid processes are launched once, for
  N's windows; whatever the app mints beyond N's count is the app's business and shows up as surplus).
* `run_load` computes `protected: HashSet<Address>` = live windows present at load start that are
  **not** on N (taken after the scoped clear). `place_live` skips protected addresses, so the Placer
  can never claim, move, float, or close another workspace's window. Nothing in the scoped path
  issues `Op::FocusWindow`/`FocusWorkspace` toward other workspaces except the final
  return-to-start, which is the v1 behaviour (`restore_workspace` captured before load).
* Placer targets = the N slice only, so no other workspace's saved geometry is applied.

**Known side effect [FLAG Q10]:** `exec` opens new windows on the *active* workspace; if the user is
on workspace M while loading N, the transient window reflows M's tiling (addresses are untouched but
geometry shifts briefly). Plan follows the brief (v1 return-to-start, no pre-switch). Alternative: focus
N before launching, return afterwards.

**`--simulate`:** header line `Scoped to workspace N: closing K windows, launching G groups` plus the
usual exec/dispatch lines for the slice only; the would-be protected pids ("shared with other
workspaces: not signalled") are listed from a live client read when Hyprland is reachable (skipped
otherwise).

**Touched:** `main.rs`, `session.rs` (`LocalSession`, `prepare_load`, `load`, `clear` wiring),
`load.rs` (`Scope`, `clear_windows`, `wait_until_gone`, `signal_eligible`, `run_load` protected set).

## V5 — Surplus-window reporting

**Design.** After `run_load` finishes placing (end of the tail loop), if `plan.place_by_class`:
read the live list once more; `surplus` = mapped windows that are (a) not claimed by the Placer
(`Placer::claimed_addresses()`), and (b) not in `protected` (scoped load only). Store as
`LoadReport.surplus: Vec<Client>`; print next to the unmatched report:

```
Windows not matched to any saved client: N
  surplus 0x… class='…' title='…' workspace=W
```

Report only; no dispatch is sent for them. Legacy plans (`place_by_class == false`) print nothing —
no claim model exists there and v1 output must stay identical.

`session.rs::load` prints (in order): the existing `Placed X windows, Y saved windows not matched`
line (unchanged text), then shortfalls (V3), then surplus (V5).

**Note [FLAG Q11]:** a full load clears first, so a window opened *between save and load* is closed by
the clear unless it survives (tray apps) — acceptance 5 is exercisable as written with
`--adjust-clients-only` or with windows that appear during the load; tray survivors will show up as
surplus, which is truthful.

**Touched:** `load::{Placer::claimed_addresses, run_load, LoadReport}`, `session.rs::load`.

## 7. Phase 2 fixed point (criterion 6)

The multiset (class, workspace, floating, position, size, argv) is unchanged by V1/V3/V4/V5. V1's
`cd … &&` wrap changes neither the window's process argv nor its pid. V2 is the risk and is handled
explicitly: (a) terminal-argv wrapper stripping at capture (V2.1), (b) fingerprint foreground
component = resolved relaunch command + cwd (V2.6). A regression test builds a snapshot with a
`claude` foreground, "loads" it through the planner, synthesizes the post-load process state
(terminal argv containing the wrapper; fg argv `claude --continue`) via `FakeProc`, re-captures, and
asserts `fingerprint(before) == fingerprint(after)`.

## 9. Risks

1. **Fixed-point regression through terminal wrappers** — the largest risk; mitigated in §7 but it is new
   logic in the save path.
2. **Secrets in `clients.json`** — recorded foreground argv (e.g. `mysql -pSECRET`, tokens in flags) widens
   what snapshots hold; argv already carries this for windows. Document in README; consider a future
   redaction setting (not in scope).
3. **Verbatim replay (DEC-2 default) of non-idempotent commands** — `make install`, `git commit`, `dd`, etc.
   would re-run on load. Decided default; the `unlisted = "prompt"` setting is the escape hatch.
4. **Terminal exec-introducer syntax** is per-terminal and unverifiable from here; unverified terminals
   degrade to a clean prompt (safe).
5. **Shared-pid terminals** (server mode) get no foreground restore — silent limitation, warned at save.
6. **V3 double-launch** for single-instance apps that raise their existing window instead of minting;
   bounded and report-only. Slow-start double launch mitigated by Q1.
7. **`/proc` visibility** — hidepid or a different uid hides foreground programs; capture degrades to
   "no record" without failing the save.
8. **Public-API churn** — `LocalSession`, `SavedClient`, `LoadPlan`, `ExecEntry` literals change (new
   fields); matters for upstream release; builder/`new` helpers reduce future breakage.
9. **New dependency (`toml`)**; mitigated by keeping it as the only addition.
10. **Scoped load disturbs active-workspace tiling** (Q10).
11. **Shell quoting layers** — mitigated by positional parameters; covered by real-`sh` tests.
