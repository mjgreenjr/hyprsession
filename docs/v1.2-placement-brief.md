## 2. Requirements

R1 — Self-detaching load (ruled Oct 28, still unimplemented).
`load` must detach itself: no setsid/nohup wrapper, and the caller's
terminal closing mid-load must not affect it. Minimum: load mode.

R2 — Pointer independence. Placement reproduction must not depend on
the USER's pointer position: same snapshot, same layout, pointer
anywhere at load start. The current fallback ("the saved tree is not
one dwindle grows with the pointer at (x, y)") is a correctness
dead-end — fallback placement must reproduce the saved tree, not
approximate it via growth order. Mike's position, and it is a product
requirement, not a test nicety: he cannot promise an identical pointer
position across stages of a test the tool itself keeps blowing up —
and a restore whose correctness needs one is fragile by construction.

R2a — Pointer steering is PERMITTED (Mike, Oct 30, supersedes the
DEC-D no-pointer-steering constraint). First establish where the
pointer dependence actually lives: the spike confirmed pointer-split
growth only on the workspace being viewed; whether the on-screen
pointer (sitting on the source workspace, moves sent with
follow = false) shapes trees on hidden workspaces was never isolated,
and tonight's fallback-set change is confounded (pointer and saved
trees both changed between loads). If the dependence is real,
the loader MAY move the pointer where placement needs it during a
load — a load already closes every window the user has; steering the
pointer for its duration is minor by comparison. If it steers, it
must restore the pointer to its pre-load position when finished.
Independence by construction remains acceptable; independence by
pointer control is now equally acceptable.

R3 — One-generation convergence. A workspace placed by the fallback
path in generation N must save back identically in generation N+1.
Needing a second cycle to settle (WS10's behavior) is not a fixed
point.
