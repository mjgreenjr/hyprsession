Branch `v1.2/plan`. Rulings applied: DEC-D ratified (queue + computed order alone — no pointer steering, no
float/unfloat, no workspace switching); claiming frozen (OQ-3); floating windows unchanged; acceptance is

implementing. Your playtest is the verdict.**

Behavior: floating windows are placed on claim exactly as in v1.1. Tiled windows are claimed as before but their
placement ops are sent together per workspace, in the order that makes dwindle regrow the saved tree for the
pointer position as found. Fallback to saved reading order (reason printed) if: layout is not dwindle,
`dwindle:force_split` is not 2, the pointer is unreadable or exactly on a leaf boundary, or the saved rectangles
are not a tree dwindle grows at that pointer. The pointer is only read (before and after each flush; a change is
reported). Windows destined for the workspace visible at load start receive no move (OQ-1).

## Playtest protocol (convergence, DEC-A)

Pick a workspace you can reload (e.g. 4 or 7) holding ≤3 tiled windows; same-class terminals with distinct working
directories are the sensitive case. Park the mouse pointer somewhere stable and **do not touch it during any load**
(the order is computed for the pointer as found).

```bash
git pull && git checkout v1.2/plan && cargo build --release
```
```bash
fp() { jq -r --argjson ws "$2" '.[] | select(.workspace.id == $ws) | [.class, .workspace.id, .floating, (.at|@json), (.size|@json), (.argv|@json)] | join("|")' "$1" | sort; }
S=${HYPRSESSION_PATH:-$HOME/.local/share/hyprsession}
WS=4   # your workspace
./target/release/hyprsession save v12-a
./target/release/hyprsession load v12-a      # wait for "Finished loading session"
./target/release/hyprsession save v12-b
./target/release/hyprsession load v12-b      # wait again
./target/release/hyprsession save v12-c
diff <(fp $S/v12-b/clients.json $WS) <(fp $S/v12-c/clients.json $WS) && echo "B==C EMPTY"
diff <(fp $S/v12-a/clients.json $WS) <(fp $S/v12-b/clients.json $WS) || true   # A->B: reported, geometry-only tolerated
```

**Pass:** diff(B, C) EMPTY on all six fields including tiled `at`/`size`. **Report back:** both diffs and, for each
load, the lines `Workspace N: … placed in computed insertion order` or `… saved reading order (reason)`. A
reading-order line means the computed path was not used there — tell me the reason; it is data, not necessarily a
bug. Also note any flicker on the visible workspace, load wall-clock versus v1.1, and any "pointer moved" warning.
If time allows, repeat with the pointer parked elsewhere, and once with `--workspace N`.

Known limits: windows for the starting workspace keep arrival order; dragged (non-50/50) dividers are not
restored; per-workspace layout rules are not consulted; the committed spike script is not byte-identical to the
instrument that produced spike #2's results.
